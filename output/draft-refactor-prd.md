# Draft Page Refactor — PRD

## 1. Background & Motivation

当前 Draft（客户稿）页面存在两个严重的可用性问题，直接影响用户审阅生成文稿的效率：

1. **排版混乱**：客户稿视图中的标题和正文视觉层次不够分明，生成的 markdown 内容缺少自动排版处理，导致全部文字"混成一堆"，用户无法快速定位章节结构。
2. **右侧候选材料区域过长**：Citations、Retrieval Trace、Tables & Figures、Assumptions 四个区块全量堆叠在 360px 宽的右栏中，每个候选材料的全部详情都直接展示，导致纵向内容极长，严重干扰左侧客户稿的阅读体验。

## 2. Objectives

| 目标 | 衡量标准 |
|------|---------|
| 标题与正文视觉层次清晰可辨 | H1/H2/H3 在字号、间距、颜色上有明显差异 |
| 自动排版提升阅读体验 | 无需手动调整即可获得类似技术文档排版效果 |
| 候选材料不再堆叠过长 | 右侧面板仅显示摘要行，候选数量不受限制但不影响主视图 |
| 详情通过浮窗展示 | 点击后弹出适配屏幕的大浮窗，分类分行展示详情 |
| 不引入破坏性变更 | 所有现有功能（编辑、保存、重生成、引用选择）保持正常 |

## 3. User Stories

### US-1: 自动排版的文章阅读体验
> 作为一名售前工程师，我希望在客户稿视图中看到排版清晰的文章，标题和正文有明显的视觉层级区分，这样我可以快速扫读并定位需要修改的段落。

#### 验收标准：
- H1 标题字号 ≥ 1.5rem，使用深色加粗，上方有明显的间距分隔
- H2 标题字号 ≥ 1.25rem，带有左侧装饰线或颜色区分
- H3 及以下标题有合理的递减层级
- 正文段落使用 1.7+ 行高，段间有 1.5em 以上间距
- 列表项有清晰的缩进和标记
- 表格保持已有的圆角 + 边框样式

### US-2: 有限展示 + 全部浮窗
> 作为一名售前工程师，我希望右侧面板最多只显示 3 个候选材料卡片，避免堆叠过长影响客户稿阅读；同时有一个"查看全部"入口，可以在浮窗中看到所有候选材料。

#### 验收标准：
- 右侧面板中 Citations 和 Tables & Figures 各最多展示 3 个候选材料卡片
- 每个卡片显示标题 + 类型 badge + 相关度分数 + 来源摘要
- 当候选材料超过 3 个时，显示"查看全部 N 个候选材料"按钮
- 点击"查看全部"按钮后，弹出大浮窗，分类（Citations / Recommended Assets / More Candidates）展示所有候选材料
- Retrieval Trace 等调试信息默认折叠

### US-3: 单项详情浮窗
> 作为一名售前工程师，我点击某个候选材料卡片后，希望看到一个足够大的浮窗来展示该材料的完整详情，里面的信息要分类、分行排列。

#### 验收标准：
- 点击右侧面板中的某个候选材料卡片后，弹出详情浮窗（适配屏幕，max-w-5xl / 1024px，max-h-[85vh]）
- 浮窗内按分类展示：基本信息 / 图片预览 / 内容预览 / 分数细节
- 浮窗内的图片如果是视觉资产，可以正常加载并显示
- 浮窗支持 ESC 关闭 和 点击遮罩关闭
- 浮窗中保留"选中此依据""仅用此依据重写""插入正文"等操作按钮

### US-4: 全部候选材料浮窗
> 作为一名售前工程师，我点击"查看全部候选材料"按钮后，希望看到一个大浮窗，把所有候选材料按类别分行展示，方便我对比和选择。

#### 验收标准：
- 浮窗内按类别分区展示：Citations / Recommended Assets / More Candidates
- 每个分区内的候选材料以紧凑卡片形式排列
- 点击某个卡片可以展开该项的详情（内联展开或切换到详情视图）
- 浮窗支持 ESC 关闭 和 点击遮罩关闭

## 4. Scope

### In Scope
- MarkdownArticle 组件的排版样式强化
- SectionBlock 组件中右侧面板的交互重构（紧凑列表 + 浮窗详情）
- 客户稿视图中 previewSegments 的自动排版处理

### Out of Scope
- 后端 API 变更
- 编辑模式（分段编辑 / 源码模式）的排版变更
- 其他页面（Outline、Evidence、Export 等）的重构
- 新增依赖包

## 5. Risks

| 风险 | 缓解措施 |
|------|---------|
| SectionBlock.tsx 文件过大（1599 行），重构风险高 | 逐步拆解，每次只修改一个关注点 |
| 浮窗组件可能影响已有 Dialog（Citation 详情） | 复用已有 shadcn Dialog 组件，保持一致的 z-index 层级 |
| 排版样式变更可能影响分段编辑中的 ReadonlyBlock | 排版样式限定在客户稿视图的 prose 区域 |
