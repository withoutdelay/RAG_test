# Reuse-First 前端迭代提案

## 背景描述
目前的前端工程虽然已有各类页面雏形（大纲页、章节页、校验页），但在实际产品体验上仍然存在“过度黑盒”的隐患，导致用户无从把控具体的生成过程与引用的素材（Assets）。本次提案的根本目标，是在 **不改动一切后端代码（含 API 定义和数据库结构）** 的前提下，彻底疏通并固化大纲确认和章节逐条审计这两个人为审核断点。

## 技术方案摘要
1. **数据与类型清洗**：重构 `types.ts` 契约，以确保在客户端流转的大纲元数据被无损地保存与再提交。
2. **流程阀门**：基于大纲状态 (`outline_status`) 在全局状态或局部路由做拦截，确保不可绕过审批直接进行子集章节生成。
3. **显性化指引与提醒**：对返回的校验日志 (`Validation`)与推荐资产 (`Recommended Assets`) 提供差异化强提醒UI（如警告徽标或独立折叠屏），并将用户的决定（`Resolve/Reject`）重新桥接回主产品工作流中。
4. **统一用户交互语义**：剔除带有绝对自动化歧义的组件文字描述或误导性Emoji图标，回归严肃且专业的操作用语。

## 预估交付清单
- `Outline` 页面全面重构及逻辑透传
- `Sections` 页面策略渲染与引文卡片扩展
- `Validation` 报错信息分组与逐条处理组件
- `frontend/src/lib/types.ts` 等全局声明更新
